# Module: `export_model.py`

**Stage 4 of the pipeline — Export**

Source: [`src/export_model.py`](../../src/export_model.py)

> **Axis convention**: IFC world coordinates are **Z-up** (X=right, Y=depth, Z=up). All three export functions convert to **Y-up** (X=right, Y=up, Z=-depth) which is the standard for OBJ, glTF, Blender, and Three.js.
> The transform applied per vertex is: `(x, y, z_ifc)` → `(x, z_ifc, -y)`

---

## Responsibility

Write the assembled geometry to disk in three independent formats. Each export function is fully self-contained — they can be called individually by Phase 2+ modules without running the full pipeline.

---

## Public API

### `export_obj(elements, output_path)`

```python
def export_obj(
    elements    : List[ElementData],
    output_path : str | Path,
) -> Path
```

Writes a Wavefront OBJ file. Each element becomes a named group: `<storey>__<ifc_type>`. The element's GUID is stored as a comment directly above the group for traceability in Blender / MeshLab.

**Faces are 1-indexed** (OBJ standard). The vertex offset is tracked across elements so the single output file has globally unique indices.

Returns the resolved `Path` of the written file.

---

### `export_glb(elements, output_path)`

```python
def export_glb(
    elements    : List[ElementData],
    output_path : str | Path,
) -> Path
```

Exports binary glTF 2.0 (`.glb`) via `trimesh.Scene`. Each element is added as a separate geometry node named by its GUID, with vertex colors applied per IFC type using the fixed color palette.

Returns the resolved `Path` of the written file.

---

### `export_elements_json(elements, output_path)`

```python
def export_elements_json(
    elements    : List[ElementData],
    output_path : str | Path,
) -> Path
```

Writes the lightweight GUID index. **No mesh data is included** — only metadata and bounding boxes. This is intentional: the file stays small even for buildings with thousands of elements, and it forms the Phase 2 linkage layer.

Returns the resolved `Path` of the written file.

---

## Output Formats

### OBJ (`model.obj`)

```obj
# IFC -> OBJ export -- generated by indoornav pipeline

g Ground_Floor__IfcWall
# GUID: 2O2Fr$t4X7Zf8NOew3FLXY
v 1.234000 0.000000 0.000000   <- (x, z_ifc, -y_ifc) = Y-up
...
f 1 2 3
```

**Axis**: vertices are output as `(x, z_ifc, -y_ifc)` — the IFC Z axis becomes the OBJ Y (up) axis.  
**Groups** named `<storey>__<ifc_type>` (e.g., `Ground_Floor__IfcWall`)  
**GUIDs** stored as comments above each group for traceability  
**Compatibility**: Blender (correct Y-up on default import), MeshLab, AutoCAD, Three.js `OBJLoader`, dashboard viewer

---

### GLB (`model.glb`)

Binary glTF 2.0 via `trimesh.Scene.export(file_type="glb")`. Structure:
- Vertices converted to Y-up (`verts_yup = [x, z_ifc, -y_ifc]`) before adding to trimesh
- Each element is a separate geometry node named by GUID for addressability
- Vertex colors applied per element (matching the IFC type palette)
- No textures or normal maps in Phase 1

**Compatibility**: Any glTF 2.0 viewer:
- [gltf-viewer.donmccurdy.com](https://gltf-viewer.donmccurdy.com) (web, drag-and-drop)
- Blender (File > Import > glTF 2.0)
- Unity, Unreal Engine
- Three.js `GLTFLoader`, Babylon.js
- IndoorNav `dashboard/index.html`

---

### `elements.json`

```json
{
  "2O2Fr$t4X7Zf8NOew3FLXY": {
    "ifc_type": "IfcWall",
    "storey":   "Ground Floor",
    "bbox": {
      "min":  [1.23, 0.00, 0.00],
      "max":  [5.67, 0.00, 3.00],
      "size": [4.44, 0.00, 3.00]
    }
  },
  ...
}
```

This file is the **primary linkage layer** for downstream phases:
- Phase 2 structural analysis: GUID → load geometry on demand
- Web viewer: GUID → highlight/inspect element on click
- Seismic simulation: GUID → storey → floor-level response

## Design Notes

- **Parent directory creation**: All three functions call `output_path.parent.mkdir(parents=True, exist_ok=True)` — the `outputs/` directory is created automatically if it doesn't exist.
- **Each function is independent**: You can call `export_elements_json()` without calling `export_glb()`. No shared state.
- **trimesh is required only for GLB**: `export_obj()` and `export_elements_json()` use only stdlib + numpy, so they work even if trimesh is not installed.
- **Process=False in trimesh**: `trimesh.Trimesh(process=False)` skips vertex/face merging since the geometry is already clean from IfcOpenShell.

## Example Usage

```python
from load_ifc import load_and_validate
from extract_geometry import extract_all_elements
from export_model import export_obj, export_glb, export_elements_json
from pathlib import Path

ifc_file, _ = load_and_validate("data/raw/building.ifc")
elements, _ = extract_all_elements(ifc_file)

out = Path("outputs")
export_obj(elements, out / "model.obj")
export_glb(elements, out / "model.glb")
export_elements_json(elements, out / "elements.json")
```
