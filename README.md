# IndoorNav

IndoorNav converts IFC building models into 3D assets and, optionally, a physically constrained indoor navigation graph. It also includes a browser-based 3D viewer with client-side route calculation.

## Capabilities

- Opens IFC files with IfcOpenShell and reads project, building, and storey metadata.
- Extracts world-coordinate triangulated geometry, grouped by storey and IFC class.
- Exports OBJ, GLB, a GUID-to-bounding-box index, and a color-coded PNG render.
- Optionally builds a multi-floor graph from spaces, doors, walls, and stairs, then writes a validation report.
- Provides A* and Dijkstra routing APIs, accessibility and crowd-weight options, CCTV-to-node mapping, and person-counting helpers.
- Includes a single-page dashboard for viewing OBJ/GLB models and navigation graphs.

The main pipeline does not automatically run camera detection or compute a route. Those are separate APIs and dashboard workflows described below.

## Requirements

- Python 3.10 or newer.
- An IfcOpenShell wheel compatible with your Python version and operating system.
- A modern browser for the dashboard. It loads Three.js from a CDN, so the first load needs internet access.

From PowerShell at the repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Navigation graph generation and its tests also need packages not currently listed in `requirements.txt`:

```powershell
python -m pip install networkx shapely
```

Crowd detection is optional. Install OpenCV for the HOG fallback, or install both packages to use YOLOv8:

```powershell
python -m pip install opencv-python ultralytics
```

The YOLO model (`yolov8n.pt`) is downloaded automatically the first time it is used. If an IfcOpenShell wheel is unavailable through pip, use the compatible package from [IfcOpenShell releases](https://github.com/IfcOpenShell/IfcOpenShell/releases) or install through conda-forge.

## Quick Start

The repository includes `data/raw/Grethes-hus-bok-2.ifc` as an input example. Run the model pipeline headlessly:

```powershell
python src/main.py --input "data/raw/Grethes-hus-bok-2.ifc" --no-display
```

To also build and validate the navigation graph, first install `networkx` and `shapely`, then run:

```powershell
python src/main.py --input "data/raw/Grethes-hus-bok-2.ifc" --no-display --build-nav
```

By default, artifacts are written to `outputs/`. Use `--output-dir` to choose another directory. Without `--no-display`, the pipeline also opens the interactive PyVista window; it still saves the render either way.

## CLI

```text
python src/main.py --input PATH [options]

Required:
  --input, -i PATH       IFC input file

Options:
  --output-dir, -o DIR   Output directory (default: outputs)
  --no-display           Do not open the interactive 3D window
  --types TYPES          Comma-separated IFC class filter, e.g. IfcWall,IfcSlab
  --max-elements N       Limit the number of IFC products processed
  --build-nav            Also build navigation graph and validation outputs
  --log-level LEVEL      DEBUG, INFO, WARNING, or ERROR (default: INFO)
```

Examples:

```powershell
python src/main.py -i data/raw/building.ifc --types IfcWall,IfcSlab --no-display
python src/main.py -i data/raw/building.ifc --max-elements 50 --no-display
python src/main.py -i data/raw/building.ifc -o outputs\trial --no-display --build-nav
```

## Generated Files

The default model run writes:

| File | Contents |
|---|---|
| `model.obj` | Meshes grouped by storey and IFC class; includes element GUID comments. |
| `model.glb` | Binary glTF model with per-element geometry and IFC-type colors. |
| `elements.json` | Element GUID mapped to IFC class, storey, and bounding box. |
| `render.png` | Color-coded 1920 x 1080 scene screenshot. |

With `--build-nav`, it also writes:

| File | Contents |
|---|---|
| `nav_graph.json` | Navigation nodes, edges, and graph connectivity metadata. |
| `nav_graph.gexf` | Graph export for tools such as Gephi. |
| `navigation_nodes.json` | Standalone node list. |
| `navigation_edges.json` | Standalone edge list. |
| `navigation_validation.json` | Physical-constraint checks, connectivity, issues, and metrics. |

Route results are not generated by the CLI. The Python `RouteResult` API can print or save one when a route is requested.

## Navigation and Crowd APIs

`src/build_graph.py` constructs an in-memory NetworkX graph and exports graph artifacts. `src/navigate.py` exposes `find_route()` and `find_route_by_name()` with A* (default) or Dijkstra, optional accessibility filtering, and crowd-weighted routing. A minimal in-memory example after installing the navigation dependencies:

```python
from build_graph import build_graph_from_ifc
from load_ifc import load_and_validate
from navigate import find_route

ifc_file, _ = load_and_validate("data/raw/building.ifc")
graph, nodes, edges = build_graph_from_ifc(ifc_file, "outputs")

# Replace these with IDs from `nodes` or `graph.nodes`.
result = find_route(graph, source_guid="START_NODE_ID", target_guid="DEST_NODE_ID")
result.print_summary()
result.save_json("outputs/route_result.json")
```

`src/cctv_integration.py` loads camera JSON, maps camera coverage cones to graph nodes, and reports coverage. `src/crowd_detection.py` detects people in images or streams and can simulate counts. `update_crowd_weights()` in `navigate.py` applies camera counts to incident edge costs. These modules are building blocks; the main CLI does not orchestrate live cameras or update graph outputs automatically.

## Dashboard

Open [dashboard/index.html](dashboard/index.html) in a modern browser. Load `outputs/model.obj` or `outputs/model.glb` with **Open File** or drag and drop. Load `outputs/nav_graph.json` the same way to show graph nodes and edges and calculate routes in the browser. The dashboard also provides model layers, storey visibility, orbit/wireframe controls, screenshots, and a walk-mode viewer.

The **Load Graph** button fetches `outputs/nav_graph.json` relative to the dashboard page; when opening the HTML directly from disk, use the file picker to load the graph instead. The page uses Three.js from `unpkg.com`.

## Tests

Run the navigation unit tests with:

```powershell
python -m unittest discover -s tests -v
```

The current navigation suite has eight synthetic cases covering wall blocking, doors, floor transitions, accessibility, and crowd-weighted route selection. Navigation test dependencies are `networkx` and `shapely`. The suite does not run a full IFC extraction integration test.

## Implementation Notes

- IFC schema detection is handled by IfcOpenShell; behavior depends on the installed IfcOpenShell build and the input file.
- The navigation builder currently creates stair transitions from `IfcStairFlight` or, when none exist, `IfcStair`. Elevator edges are supported by routing data structures, but automatic elevator extraction is not implemented in the IFC graph builder.
- A validation report can pass with warnings or multiple connected components. Review `connected_components` and the reported issues before relying on route availability.
- The graph builder relies on IFC spaces, doors, and wall geometry. Model quality and spatial relationships affect the resulting graph; validation is a diagnostic, not a guarantee of complete real-world navigability.
